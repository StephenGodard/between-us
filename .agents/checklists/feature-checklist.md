# Feature checklist

- [ ] One observable outcome and one horizon are clear; the feature links to its exact parent PRD and requirement IDs.
- [ ] Each behaviour preserves the PRD's source and decision state; hypotheses and gaps are visible.
- [ ] Entry, end, exclusions, dependencies and acceptance evidence make the feature independently reviewable.
- [ ] Demo-only behaviour is separate from future real-person safety, archive and operational behaviour.
- [ ] The selected PRD requirements are covered by features or explicitly deferred; reciprocal links and IDs agree.
- [ ] No feature claims PRD approval, architecture acceptance, build readiness or implementation authority without the corresponding decision.
