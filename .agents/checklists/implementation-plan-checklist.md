# Implementation plan checklist

- [ ] Product and technical context, `constraints.md`, `stack.md`, applicable ADR and relevant engineering guides were read before planning; selected story, horizon, source statuses and conflicts are identified.
- [ ] Every acceptance criterion maps to an implementation slice and a meaningful verification check.
- [ ] Client, backend, state, security and deployment boundaries follow the applicable ADR and inspected code.
- [ ] Slice order, dependencies, likely file areas and integration points let a developer start without guessing a material requirement.
- [ ] Open decisions are distinguished from reversible implementation choices; material gaps set `BLOCKED`.
- [ ] Planned checks are `NOT RUN`; no implementation, device, privacy or production claim is implied.
