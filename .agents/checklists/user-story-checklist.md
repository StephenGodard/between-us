# User story checklist

- [ ] One user-visible outcome, actor, value and delivery horizon are clear and supported by the selected PRD and feature.
- [ ] Exact parent paths, statuses, feature ID and PRD requirement IDs resolve; each acceptance criterion cites a supported functional source.
- [ ] Entry, end and Given/When/Then outcomes are observable without invented labels, values or behaviours.
- [ ] Client and server responsibilities, technical constraints and dependencies reflect the current technical context and accepted ADR; unresolved design remains open.
- [ ] Exclusions keep the fictional demo separate from the later real-person service.
- [ ] Material gaps produce `BLOCKED`; otherwise the story is `READY FOR REVIEW` until explicitly approved.
- [ ] Selected requirements and feature behaviours are covered or deliberately deferred in the story index; reciprocal links agree.
- [ ] Verification evidence distinguishes checks performed from `NOT RUN` checks and does not imply implementation or build readiness.
