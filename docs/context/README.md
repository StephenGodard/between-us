# Project context

This directory groups the sources agents need before product or architecture work.

| Area | Start here | Scope |
| --- | --- | --- |
| [Product context](product-context/README.md) | Product summary, exact user answers, discovery, BA brief, evidence, and research | Living functional evidence, decisions, and open questions |
| [Experience context](experience-context/README.md) | Demo journey, screen hypotheses, visual direction and UX questions | Living experience synthesis from product decisions |
| [Design context](design-context/README.md) | Landing-derived visual proposal, interface adaptations and mockup coverage | Living design synthesis for reviewable screens |
| [Technical context](technical-context/README.md) | Observed prototype facts, technical constraints, options, and current decision state | Technical synthesis for the selected delivery scope |
| [Hackathon source](hackathon-kickoff.md) | Summary of the [supplied PDF](DevDay-Paris-Hackathon-Kickoff.pdf) | Event constraints, not product requirements |

Read the product sources before drawing technical conclusions. [Architecture decision records](../adr/README.md) are linked from the technical context: each ADR explains one choice and its rationale, while the technical context summarizes the current state. A proposed ADR does not become an approved decision by being linked here.
