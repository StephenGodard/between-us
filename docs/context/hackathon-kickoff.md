# Hackathon event context

Source: `docs/context/DevDay-Paris-Hackathon-Kickoff.pdf` (10 pages, 24 October 2026). This file records event information only. It does not define the project idea, users, product requirements, chosen track, or claimed impact.

## Tracks and theme

- Page 2 lists three tracks: **Impact**, **Hardware**, and **Build in public**. Teams may choose one or more tracks when registering (page 10).
- Page 3 lists **Climate action** under Impact, with energy, waste, and emissions as examples. Disability inclusion, poverty reduction, and new opportunities are also shown under Impact.
- Page 4 describes Hardware examples. Page 5 describes Build in public and gives the tags `@borvibe`, `@openaidevs`, and `#parisdevdayhack` for sharing progress, demos, and lessons.

## Timing and submission

- The online build period is 24–25 October 2026 (page 2).
- The submission deadline is Sunday 25 October **before midnight, Paris time** (page 6).
- A two-minute pitch video is required. A project link and GitHub repository are optional (page 6).
- The community finale is 26 October, 18:00–22:00 Paris time; invited winners attend the DevDay Exchange on 28 October (page 2).

## Team logistics

- Registration is once per team and requests a team name, member names and email addresses, and one or more tracks (page 10). Do not copy personal details into a project brief unless the user explicitly supplies them for that purpose.

## BA use

When the user supplies a project idea, use this event context to ask whether the intended track is Impact and which problem the idea addresses. Test whether the proposed first version can be demonstrated and explained in a two-minute pitch by the submission deadline. Keep these as event constraints; do not infer an environmental benefit, impact metric, or product feature from the slide examples.
