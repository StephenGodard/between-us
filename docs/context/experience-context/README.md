# Experience context

Read the [current experience context](experience-context.md), [two participant flows](user-flows.md), [conversation UX options](conversation-ux-options.md), [selected subject-led entry](subject-entry-flow.md) and [lightweight entry-flow experiment](entry-flow-experiment.md) after the [product context](../product-context/README.md) and before designing screens or writing interface copy. They record the fictional-demo journey, the owner's selected entry and optional voice (A-32), reciprocal messaging (A-28), candidate visual patterns, and questions still to resolve. The flows reuse the structure of the owner's AnimeSphere UX page as requested (A-27), without importing its product assumptions.

This is living design context, not a separately approved specification. The [initial PRD revision](../../prds/entre-nous-initial.md) and [reviewable demo features](../../features/README.md) define requirements and acceptance evidence; the [intake](../product-context/intake/espaces-ecoute-ephemeres.md) preserves exact user decisions. The [technical context](../technical-context/README.md) records implementation constraints. The exploratory [`prototype/`](../../../prototype/README.md) is not design authority.
