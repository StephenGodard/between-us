# Technical context

This directory is the technical entry point for agents. Read the [technical context](technical-context.md) for the current scope, observed prototype, architecture options, decision status, and open questions. It is **DRAFT**.

An ADR is part of the project's technical knowledge, but it is a separate decision record. The technical context links to each relevant ADR and summarizes its decision status; the ADR keeps its options, rationale, consequences, and review trigger. See the [ADR index](../../adr/README.md). The current web demo infrastructure ADR is **PROPOSED**, so its Nuxt rendering and hosting recommendation is not approved.

[Constraints](constraints.md) and [stack](stack.md) are placeholders to complete together before construction of the solution. Until then, use this technical context and the ADR status for architecture analysis. [Guidelines](guidelines/README.md) have not been approved either.

Read the [product context](../product-context/README.md) and cited intake answers before changing technical decisions. The existing [`prototype/`](../../../prototype/README.md) is exploratory code, not a product requirement or build baseline. Future implementation belongs in [`src/`](../../../src/README.md) after scope and architecture are chosen.
